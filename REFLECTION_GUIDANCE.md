# Reflection-render guidance for flow-matching panoramas: status report

**Status (2026-11-22): implemented end to end and evaluated on all four public bag-of-chips datasets.
The gradient guidance does not work very well.** It reliably steers the generator toward the right
light layout, but its measurable gain over the plain splat panorama is small and not robust. On two of
the four datasets it is neutral or negative, and on one it does nothing at all. The rest of this file
records what was built, what was measured, and why it falls short.

## 1. Idea

This replaces part (A) of the pipeline (bag-of-chips inputs → panorama → Pano2Room 3D room). The
bag-of-chips SRM/splat panoramas are too noisy, so the panorama `I` is **generated by a frozen
flow-matching model**, and each sampling step is nudged by the gradient of a plain reflection-render
loss. **No network is trained**: there is no SRM, refinement net, weight net or neural renderer.

- **Diffuse** (fixed): per mesh point, the minimum colour across views (paper's diffuse estimate). In
  practice this was the dataset texture (`--diffuse texture`), or a cylinder min-colour atlas for Cans
  (`--diffuse min`, `label.py`).
- **Render** (linear in `I`): `photo_lin(x) = diffuse(x) + g ⊙ lin(I)[r(x)]`.
  - `r(x) = 2(n·v)n − v` is the mirror reflection direction.
  - `I` is flipped to the lookup layout, area-pooled to 512×256 and linearised with `^2.2`.
  - `g` is a per-channel gain, fit in closed form at every step.
- **Loss**: MSE over the selected object pixels of all training views, with photo pixels at or above
  0.98 excluded (clipped highlights).
- **Guidance**: at each step, `v ← u_θ(x_t) + λ·(‖v‖/‖∇L‖)·∇L`, with each element clipped to
  3·rms(v). The render gradient is computed independently of the velocity inference.
  - In the latent model, `∇L` is backpropagated through the frozen VAE decoder: render → panorama
    pixels → decoder → latent.
  - In the pixel model, the decoder is the identity.
- **Self-recurrence (re-noise)**: each guided step is taken K times. Between passes the latent is
  re-noised from σ_{i+1} back to σ_i with the exact flow kernel
  `x = a·x' + √(σ_i² − (a·σ_{i+1})²)·ε`, where `a = (1−σ_i)/(1−σ_{i+1})`. This gives attention extra
  passes to blend the guided and unguided regions.

## 2. Implementation

| File | Role |
|---|---|
| `fm_guide.py` | data (pixel selection, samples), renderer, loss, `Guide` (x_t / x̂₀ guidance, clip, re-noise), GT scoring, figures |
| `third_party/DiT360/pipeline.py` | DiT360 pipeline (FLUX.1-dev + panorama LoRA), copied with a guidance hook and the self-recurrence loop |
| `fm_guide_pixel.py` | same method with **PixelDiT-1300M** (pixel-space flow DiT, no VAE) |
| `results/paper_*_ref/` | ground-truth and paper panoramas extracted from the PDF (Fig. 5) |

**Models.**
- Latent: FLUX.1-dev + Insta360 DiT360 LoRA, 2048×1024, 28 Euler steps. Weights are in
  `/overflow/xiang/hf_cache`.
- Pixel: NVIDIA PixelDiT-1300M-1024px (BiliSakura diffusers port), 1408×704, CFG 2.75, with a random
  azimuth roll per call. It is **not** panorama-trained; no pixel-space panorama model exists.

**Best setting:** `--guide-on xt --sat 0.98 --clip 3 --recur 3 --lam 0.333`, neutral prompt
"This is a panorama. The image shows an indoor room."

**Data.** The datasets come from grail.cs.washington.edu/projects/bagofchips: Cans, corncho1, labcat
and bowls. Ray-trace caches live in `/overflow/xiang/scenes/<name>/cache`. Each dataset is split into
training views and held-out test views at the edge of the capture.

**Metrics.**
- **Re-render test PSNR**: the object pixels of the held-out photos, re-rendered with the panorama.
- **GT PSNR/SSIM**: against the paper's ground-truth panorama (Fig. 5(d)), after gain, blur and
  azimuth/mirror alignment (`envmap.compare`). It is reported on the texels the object observed, and
  on the whole visible GT.

## 4. Why it does not work very well

1. **The improvement is small and within seed noise.** The best corncho1 gain over the splat is
   +1.0 dB at seed 1 and +0.15 dB at seed 0, from only 2 seeds per setting. On the re-render metric,
   guided panoramas are at best ≈ the splat (corncho1, bowls) and 2 dB worse on Cans. The splat is the
   exact least-squares optimum of this blurry 512×256 loss, so the render loss can only pull the
   generator toward the splat; it cannot add information the reflections do not contain.
2. **The diffuse layer is the weak link.** On labcat the dataset texture already contains the
   highlights: the residual photo − diffuse averages −0.001, and 52 % of it is negative. The
   closed-form gain therefore fits g = 0, the render ignores `I`, and **the gradient vanishes**. The
   loss is identical to 5 digits across all runs. Corncho1's residual is also negative for 46 % of
   pixels.
3. **Guidance and prior do not communicate.**
   - The gradient reaches only the latent patches above reflected texels (the upper ~60 % of the
     sphere), because the VAE decoder is local and the gradient never passes through the transformer.
   - The prior fills the rest independently, leaving a visible seam and two different camera heights.
   - Re-noising (K=3) helps only when λ is reduced by K. Otherwise it simply triples the guidance push
     and gets worse.
4. **There is a narrow usable strength window.**
   - λ ≥ 3 overfits the noisy reflections: maze-like and fiery artifacts, −1 dB GT PSNR, −0.12 SSIM.
   - Without per-element clipping, strong guidance overflows bf16 and produces NaN (black images).
   - λ ≈ 1/3 with K=3 works on corncho1, but is untested for robustness.
5. **Colour and exposure are absorbed by the per-channel gain.** The ceiling light comes out orange
   instead of warm white, and windows are bright blobs without detail.
6. **The data's viewpoint is out of distribution.** The real environment is seen from the object on
   the floor or table, whereas DiT360's prior is eye-level Matterport rooms. Every public ground-truth
   panorama is taken from the object's position, so there is no "regular view" reference among the
   released data.
7. **Pixel space does not fix it.** PixelDiT is 13× faster (about 10 s vs 130 s per sample) and
   reaches similar GT PSNR. But its exactly local pixel gradient leaves a speckled, splat-like upper
   half, and the model has no panorama prior.
8. **Evaluation is thin.**
   - Ground-truth panoramas exist for only 2 scenes (corncho1, labcat), and both are figure crops
     (upper 68 %).
   - Alignment frees gain, blur and azimuth.
   - SSIM rewards any clean room: unguided labcat rooms score 0.6 against the splat's 0.2.

## 5. Possible next steps

- **True per-point minimum diffuse for every mesh** (`--diffuse minvox`): a ~2 mm voxel `amin` over
  views. This makes the residual non-negative and fixes labcat's zero gradient.
- **Backpropagate through the transformer** (full DPS), so that attention carries the render error to
  the unobserved half.
- **More seeds** (≥ 8) per setting, with means and confidence intervals, before claiming any gain.
- **A single shared gain** instead of one per channel, to stop the colour casts.
- **Low-pass filter the pixel-space gradient**, to remove the PixelDiT speckle.
- **Synthetic test with an eye-level HDRI** (`synth.py --env`), to separate the viewpoint problem
  from the method.
- A floor-level viewpoint prompt, or guiding only early steps (`--stop-frac 0.5`).

## 6. Reproduce

Run from the repo root, inside `srun -p gpu --gres=gpu:1`, with
`HF_HOME=/overflow/xiang/hf_cache HF_HUB_OFFLINE=1 PYTHONNOUSERSITE=1`.

```bash
# best latent setting on corncho1 (GT = Fig. 5(d))
SCENE=corncho1 python fm_guide.py --select above --diffuse texture --guide-on xt --sat 0.98 --clip 3 \
  --recur 3 --lam 0 0.333 --seeds 0 1 --prompt "This is a panorama. The image shows an indoor room." \
  --gt results/paper_corncho_ref/fig5d_corncho1_ground_truth_5376x1827.jpg --gt-rows 0.68 \
  --out results/fm_corncho1_recur3_lam033

# same setting with the pixel-space model
SCENE=corncho1 python fm_guide_pixel.py <same flags> --out results/fm_pixel_corncho1
```

Result folders:
- corncho1: `results/fm_corncho1`, `results/fm_corncho1_recur3`, `results/fm_corncho1_recur3_lam033`,
  `results/fm_pixel_corncho1`
- other datasets: `results/fm_best_{cans,labcat,bowls}`
- earlier Cans sweeps: `results/fm_guide`, `results/fm_guide_xt`, `results/fm_guide_xt_fix`

Logs are in `logs/`.
